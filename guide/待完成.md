## 问题列表

### 设计缺陷
1. **switch-case 不支持 break**：switch-case 语句中的 break 会报错 "break outside loop"
   - 状态：已修复（在 switchstat 中使用 enterblock 创建块，设置 isloop=1）
   - 优先级：中
   - 发现时间：测试 switch-case 代码示例时
   - 修复时间：2026-05-03

### 代码缺陷
1. **_ENV 寄存器被局部变量覆盖**：当声明局部变量时，局部变量从寄存器 0 开始分配，覆盖了 `_ENV` upvalue，导致后续的全局函数调用（如 print）失败
   - 状态：已修复（在 mainfunc 中设置 _ENV upvalue 为封闭的 instack=0）
   - 优先级：严重
   - 发现时间：测试位运算符时
   - 修复时间：2026-05-03
   - 影响范围：所有使用局部变量后调用全局函数的场景

2. **左移运算符编译错误**：`a << 2` 被编译成 `SHRI`（右移）而不是 `SHLI`（左移）
   - 状态：已修复
   - 优先级：高
   - 发现时间：测试位运算符时

3. **局部变量寄存器分配不一致**：在 `int a = 255` 中，表达式结果存储到寄存器 1（因为 fs->freereg = 1），但变量被分配到寄存器 0（因为 luaY_nvarstack 返回 0），导致变量和值不在同一个寄存器
   - 状态：已修复（在 mainfunc 中设置 _ENV upvalue 为封闭的 instack=0）
   - 优先级：严重
   - 发现时间：测试位运算符时
   - 修复时间：2026-05-03

4. **VM 指令 pc++ 跳过下一条有效指令**：算术/位运算指令（如 SHLI, MOD, POW）在 VM 中执行后会执行 `pc++` 跳过 MMBIN 指令，但编译器没有为类型特化指令生成 MMBIN，导致跳过下一条有效指令
   - 状态：已修复
     - 修改 `finishbinexpval_typed` 函数，生成 dummy MMBIN 指令
     - 修改 `codebinexpval` 函数，为 MOD 和 POW 生成 MMBIN 指令
   - 优先级：严重
   - 发现时间：测试位运算符和算术运算符时
   - 修复时间：2026-05-03
   - 影响范围：所有使用移位、取模、幂运算后调用函数的场景
   - 示例代码：
     ```mos
     int a = 255
     int r = a << 2  // SHLI 指令执行后 pc++ 跳过 GETTABUP
     print(r)        // 失败：attempt to call a nil value
     ```
